# MNIST 投毒验收样例：公开验证与冻结记录

当前验收代码为 `mnist_poison_attack.py`，SHA-256：`f55e2be06c8c59372a26ef87da4fd7b00adbb44a92b8d1c97a6c80c5a7721d76`。它是附加标准验收提交，原官方 Random Label Flip reference、统一 MLP、固定池与 `准确率下降 ≥ 0.05` 均保持不变。缺失门槛的校准仍使用原官方 reference；本样例只用于正式验收。

## 数据边界与选择过程

研究只读取原公开 `train.npz`（8000 张 MNIST；SHA-256：`52f58266c4ba1098e8a4ae564af2e21e1b3595dc3c701d2252123b1529e97ab9`），独立容器只挂载该文件，网络禁用，未挂载或读取隐藏 `test.npz`。所有模型训练在固定镜像 `sha256:bb3ee30c5b38c6974260387d2f0ba4de6b89c9d3954cae420ad346ea81853e4c` 内进行，NumPy 1.26.4、scikit-learn 1.5.2、BLAS 2 线程。原 MLP 参数、随机种子和早停机制完整记录在同名 JSON 中。

先在公开划分 seed=11/29 比较 27 个预先列明的标签翻转、聚类中心和簇内均匀随机候选，再在两批新的公开划分复查候选；这些标签-only策略未保持足够余量，均未采用。旧的随机9→4样例不再作为当前验收代码。各阶段最低公开下降记录在 JSON；未用隐藏标签或隐藏得分选择新算法参数。

课程允许修改像素或标签，按两者改变索引的并集计算5%样本预算。因此最终采用一个固定联合策略，并在11组公开划分验证后冻结代码；另4组全新划分2017/2053/2081/2113直接加载冻结文件复验，没有再调整算法。

## 固定联合策略与合法性

以seed=42随机排列所有数字5索引，选前`floor(0.05*N)`个；在这同一批索引，将图像替换为其余未修改数字5图像的固定随机排列循环副本，并把标签置8。每个保留字形都产生矛盾标签监督，部分字形重复两次；算法不训练代理模型，不访问文件，也不读取验证/隐藏样本。与单纯随机错标相比，它让错误监督覆盖所有保留的源类字形。

完整8000输入含722个数字5，修改400个索引，保留322个数字5。返回图像仍为`[8000,1,28,28] float32`、标签为`[8000] int64`，像素仍在[0,1]。400个图像变化与400个标签变化发生在同一批索引，并集恰好400/8000=5%，没有增加或删除样本。通过实际`contracts.check_poison`检查；输入不被原地修改，重复调用一致，覆盖全部322个保留供体。完整契约结果与索引哈希见JSON。

## 复现与检查

```sh
python tests/validate_poison_acceptance.py --public-train /public/train.npz --output /results/poison-review.json --seeds 2017 2053 2081 2113
```

脚本核对公开文件哈希，拒绝输出覆盖，先检查完整8000输入契约，再调用原课程`train_model`和`accuracy`复验指定公开划分。单元测试还覆盖像素/标签合并预算、供体范围、零预算和源类不足，不以缩小数据的测试替代完整课程验收。
