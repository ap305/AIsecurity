## 已确认的规则

- 基础题按原实验指标给出 0–100 分，平台只在更高成绩出现时更新最高分。
- 攻防题先用官方参考对手测基线，再与合格学生对手池中的真实提交交互。平台按胜率汇总，不把官方对手的连续分数直接当作排行榜成绩。
- 所有门槛使用 `>=`。合格但没有对手为 100%；正常对抗失败计入分母；未过基线、未完成、学生接口异常和系统异常不产生正式成绩。
- 官方参考对抗指标为 0 时，不能把 0 设为获胜门槛。只有存在可解释的正数粒度或原题成功标准时才允许冻结；无法解释的连续指标阻止发布。
- 01、06、31 已获用户授权采用固定数据、种子和资源预算的隔离配对重训。04、07 和其他模型题继续按各自适配后的推理/算法接口执行。
- 05 采用逐目标独立贴片评测，保留 AttackGain ≥ 0.40、HideRate ≥ 0.50。
- 题目版本变化影响当前版本排行榜，因此新题使用新编号；已有题目和历史提交由现有版本管理逻辑处理。

## 运行边界

学生代码及其模型反序列化仅在独立 worker 中运行。grader 保留正式数据、隐藏标签和教师资产，通过现有 `platform-rpc-v1` 数据协议调用 worker。双方共用题包时，worker 必须能够按可信角色选择正确公开框架。

正式平台将完整 `definition.evaluation` 传入 `context.parameters`。调用端、适配器和本地 RPC 验证必须使用这个结构。结果必须通过 `validateEvaluationResult`：`metrics` 只能包含扁平有限数值，攻防阶段不得自行返回最终总分。

学生下载包使用逐项白名单。正式隐藏标签、私有参考解答和教师评测模型不进入公开资源；本地练习从训练数据派生，不能宣称其分数就是正式成绩。31 的公开规划代理和固定训练投毒数据属于必要教学资产，单独列入允许清单。

私有样本顺序用于避免学生按输入批大小、真假固定顺序或公开生成种子猜出标签。顺序只保存在可信题包并随摘要冻结，同一题对的两个角色共用。重新构建产生的新私有数据顺序属于新的包，不能复用旧包校准证据。媒体组可通过构建参数 `--media-private-order-seeds` 复用已封存的私有顺序文件；该文件禁止作为学生资源发布。

## 构建与校准

1. 核对源压缩包摘要和安全解压结果。不要执行压缩包内的部署指令。
2. 用 `prepare_teacher_assets.py` 补齐 03 的固定语料 bigram 和 B17 的真实 AG News/BERT 参考权重。该过程记录资产摘要与实测结果，禁止合成数据回退。
   另用 `media/tests/prepare_public_training.py` 预先生成10/12独立练习缓存至 `<prepared>/public-assets`，保留其生成参数和摘要。构建只复制这些已验证缓存，不将正式数据生成链公开给学生。
3. 从 `docker/course-v3-evaluation` 构建运行镜像，固定镜像摘要并加入平台允许列表。生产设置 `EVALUATION_REQUIRE_IMAGE_DIGEST=1`。
4. 运行 `build_all.py`。生产构建要求 `--image NAME@sha256:DIGEST`；开发镜像必须显式添加 `--allow-development-image`，不得用于发布。
5. 输出 `manifest.json`、`build-evidence.json` 和五组题目/评测包/资料。初始清单明确为 `requiresCalibration=true`、`deploymentReady=false`。
6. 按 `adversarial/api-pools.json` 在全局 API 池配置独立固定参数绑定。同一对题共用模型配置；部分题需要由可信 grader 动态提供 system message，不可误加固定 systemPrompt。模型密钥保留在服务器环境中。
7. `scripts/calibrateCoursePackV3.ts` 直接安装环境包并创建参考自测，不创建业务题目。用实际生产镜像和实际模型完成全部基线/对手测量，要求清理状态为 `cleaned`。断点状态绑定完整输入摘要；不确定的任务创建结果必须独立核对后恢复，不能重复提交猜测。
8. 全部测量通过后生成同目录的最终清单。最终清单冻结非零实测阈值、可解释的零参考下限及实际 API 池 ID。
9. `scripts/importCoursePackV3.ts` 使用最终清单分阶段 `prepare → self-test → publish → verify`。正式配置的自测仍必须通过；校准自测不能替代最终发布自测。未校准标记、未就绪标记和空门槛会阻止发布。

在 quiz-svc 目录运行 `pnpm exec tsx scripts/validateCoursePackV3.ts <manifest.json> --check-archives`，会校验77题范围、所有文件摘要、环境声明、公开worker挂载、题面资源链接，以及真实ZIP压缩/解压后的大小边界和内容。此步骤不执行课程代码、不访问API；需要设置同样的 `EVALUATION_ARCHIVE_PROFILE=course-v3`。

较大的 BERT/COCO 评测包需要在服务器 `api.env` 设置 `EVALUATION_ARCHIVE_PROFILE=course-v3`，只调整管理员评测包边界为压缩 640 MiB、展开 1536 MiB、单文件 512 MiB；学生上传仍受题目自身限制。API 容器需为大包解压和校验预留足够内存，可通过部署变量 `PRD_API_MEMORY_LIMIT=8g` 提高导入期间内存预算，并以实际峰值验证。内网 nginx 模板的管理员包上传入口已允许650 MiB请求；公网代理同一入口也须核对并调整，学生权重入口须允许500 MiB文件及multipart开销。不能只提高应用限制而留下代理的200 MiB限制。

## 发布与回退

### 基础17题优先发布

用户已要求基础题先发布。`scripts/certifyCoursePackBasics.ts` 从原始、摘要匹配的校准清单和状态重新读取17条真实已清理基础评测证明，核对代码、权重、包和配置绑定后生成同目录的基础题检查点。它只发送GET，不改动原状态或其锁；整包与60道攻防题保持未就绪。

导入器的显式 `--publish-ready-basics --only V3-261012-B01,...,V3-261012-B17` 仅接受完整17道已就绪、无需模型API的基础题。仍须经过 `prepare → self-test → publish → verify`，重新运行17条最终配置的Docker自测并核对全部资源。默认全量发布门禁保持原样，不能用此开关发布攻防题或未校准题。

基础题使用独立导入状态文件。后续完整校准完成时，用最终清单和另一个独立状态文件只导入、发布剩余60道攻防题；已发布基础题不由新状态接管。最终对77道新题逐项核验，并保留基础17和攻防60两个正常导入状态作为发布审计证据。

必须先通过本地测试和版本控制检查，提交代码并创建带注释的发布标签，再从干净版本构建上传。现场先读取服务器现状、保留站点备份和数据库备份，在隔离环境验证后再切换 `platform.example.com`。

不得把旧测试数据库直接切为生产。若现站仍有业务写入，应在维护窗口从当时的生产数据库重新复制和迁移，核对用户、原题和成绩数量及关键指纹，再导入本题包。前端与 API 需协调切换，保留既有域名、TLS、访问认证及其他站点路由。

切换后的验收通过 HTTP/API/资源下载完成：77 题数量与角色、题面和模板、资料摘要、真实基础提交、准入及正常 0 分、无对手 100%、学生池变化、管理员每名学生逐题得分、旧题和历史成绩。依项目约定，不进行浏览器渲染或截图验收。
