# V3 隐私与推荐题适配

范围为 A/D23、24、25、26、30、31，共 12 题。构建脚本产出的是待校准片段，不能直接发布：阈值为 `null`、`requiresCalibration=true`，由全题库聚合器保留证据并通过正式环境自测校准后冻结。

## 实际对手关系

| 题号 | 实际配对输入与可信重算 |
| --- | --- |
| 23 | 攻击者查询对手上传的 DP 模型；后台用隐藏成员标签重算 MIA，并计算防御的隐私改善与效用保留。 |
| 24 | 对手防御变换每个样本的梯度，再交给攻击者重建；后台重算 SSIM 与标签指标。真实图像、标签不进入攻击 worker。 |
| 25 | 攻击者查询对手遗忘模型；后台根据真实预测重算 AUC，并拒绝不一致的自报 AUC。 |
| 26 | 对手防御给出分割规则，可信 Mondrian 生成并检查匿名表；攻击者按公开准标识符计算距离，后台用隐藏映射重算重识别结果。 |
| 30 | 攻击者的真实伪造用户资料进入对手检测与过滤，可信 ItemKNN 重新计算曝光与效用，分母保留原真实用户集合。 |
| 31 | 攻击者实际改写的评分矩阵进入固定 MF 训练；对手提供的稳健权重实际作用于训练损失，后台重算曝光与 NDCG。 |

31 的固定预算已写入题面与冻结参数：维度 32、学习率 0.0005、正则 0.05、batch 2048、每次 80 epochs，共干净/投毒各一次与鲁棒三次，合计最多 400 epochs，种子 42/43/44、最多改写 1000 项、4 CPU、6144 MB、最长 3600 秒。训练仅运行可信固定实现；上传模型反序列化和学生回调仍在隔离 worker 中。后台记录实际训练矩阵 SHA-256；对外 metrics 只含有限数值。

## 信任边界与资源

- `bootstrap.py` 加载学生代码和上传参数；`runtime.py` 在 grader 内调用私有原评测器，通过 RPC 使用两方真实提交。学生代码不会直接加载到 grader。
- `codec.py` 仅编码有限数值、数组及显式表格；缺失评分通过独立掩码传输，不使用 pickle 传递对象。
- `grade.py` 使用生产协议的完整 `context.parameters = definition.evaluation`，入池读 `qualificationMetric`、对抗读 `successMetric`，比较统一使用 `>=`。非法材料、无效算法和基础设施错误不会伪装成正常零分。
- 公共工具包使用训练数据派生本地验证集，不公开正式测试标签、隐藏成员关系和重识别映射。24 还移除了与正式重建目标重复的公开图像。
- 23/26 的公开 dataset 只保留本地加载与算法所需的数据接口，不分发正式划分生成器、固定种子或原始划分元数据。构建时使用系统随机源生成私有置换，23 同步置换候选与成员真值，26 同步置换发布行、查询顺序与真实映射；原样本与标签不变，具体顺序封存在私有 NPZ 内并受包摘要约束，两个角色共享同一版本。公开 23 辅助图像与正式成员图像逐像素比对无交集。
- 24/25 的公开 dataset 同样仅加载本地缓存，保留归一化和本地训练所需接口，删除正式数据下载和重建路径。24 的练习训练集从排除隐藏目标后的图像另取随机半集并重建客户端划分，避免完整公开 MNIST 与练习数据的差集直接暴露八张目标；正式评测样本与教师权重不变。
- 31 的显式公开资源白名单允许教学必需的 `teacher_clean.pt` 和 `fixed_poison.npz`；不公开投毒/鲁棒参考解权重。公开 NPZ 不加载对象数组，物品名使用安全字符串。
- 对连续指标不能任意给一个很小的数作为“最小正粒度”。构建证据会标记连续指标；实测为零时，校准器必须停下等待明确成功标准。离散零参考使用有推导依据的正门槛，例如 A25 在 500 个遗忘样本、2000 个参考样本上的归一化 AUC 半步为 `0.00000125`。

这些题保留原作者的公开 MNIST/CIFAR/Adult 教学基准和冻结教师。隐去划分代码、顺序和隐藏标记解决了平台直接分发答案映射的问题，但公开原始数据可能被从外部取得并进行图像/记录指纹匹配。尤其 23 原成员与非成员分别来自 MNIST 官方训练与测试池，已知这种来源假设仍可能构造旁路。当前版本不声称消除此类公开基准固有限制，也没有擅自替换原样本或重新训练教师；若用于严格的对抗竞赛，需要另立独立数据与教师版本重新校准。

## 验收方式

`test_contracts.py` 验证数据协议、隐藏真值隔离、自报指标造假、真实改写预算和公开查询批处理。`rpc_smoke.py` 用生产导出的 worker 模板启动独立本机进程，分别运行 baseline/opponent；`validate_results.ts` 将实际结果交给生产 `composeJudge.validateEvaluationResult` 再验收。

2026-10-16 本机验收：12 项边界测试通过，12 次 baseline 与 12 次 opponent 均完成并通过生产结果解析；6 组公共工具包解压后可加载本地数据。公开接口裁剪后还重验 23/26 共 8 次真实 RPC，以及 A24、D25 两次同时涵盖双方 worker 的对手 RPC，均通过生产结果解析；24/25 的公开工具包完成解压、模块合成、数据加载、归一化、模型推理与权重导出再加载。31 两个角色的实际配对训练输入一致，真实改写 719 项，训练 400 epochs。这些本机结果用于实现验证，不能代替正式镜像内的 Docker 自测、容器清理证明和正式阈值冻结。

构建示例（输出目录须为空，正式构建须传入镜像摘要）：

```text
python build.py --source <解压题库根目录> --output <新的片段目录> --image <镜像名>@sha256:<摘要>
python test_contracts.py
python rpc_smoke.py --build <片段目录> --rpc <生产worker导出目录> --output <证据目录> --id A31 --phase opponent --timeout 3600
node <tsx>/dist/cli.mjs validate_results.ts <证据目录>
```
