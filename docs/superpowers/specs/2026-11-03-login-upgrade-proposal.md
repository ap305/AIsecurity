# 登录与账号体系升级方案

日期：2026-11-03

状态：现状调查及改造建议，尚未实施。用户已选择“先完善现有账号体系”。

适用项目：AIsecurity，正式入口 `https://www.rgznaq.com`。

## 1. 结论与范围

建议在现有账号体系上分阶段补齐功能，继续使用现有 React、Express、Prisma、PostgreSQL，不先引入独立身份平台，也不要求学生重新注册。

第一阶段优先解决改密与重置、登录保护、退出失效、网络故障导致误退出、重新登录后返回原题等问题；第二阶段再迁移服务端会话与 HttpOnly Cookie，增加设备会话管理及管理员二次验证。

本方案覆盖学生和管理员登录、注册、个人账号安全、管理员账号操作及其业务兼容。学校统一认证、短信登录作为后续可接入能力，本期不依赖校方接口或短信服务。共享类型中的 teacher/ta 枚举不代表现网已有相应人员角色，本期不据此扩展权限。

本次只进行只读调查和方案编写，没有修改生产账号、密码、成绩、评测任务、Nginx 或上线版本，也没有发起模型评测、批量重试或生产压力测试。

### 2.2 已有能力与不足

| 环节 | 当前行为 | 影响及改造重点 |
|---|---|---|
| 登录入口 | 学员、管理员两个入口；用户名和密码登录 | 保留入口习惯。角色由后端数据库确定，切换前端入口不会获得管理员权限 |
| 注册 | 学生自行注册，密码至少 6 位；学号、手机号选填 | 保留旧账号可登录；加强新建、改密规则，不能追溯性地拒绝全部旧密码 |
| 密码算法 | 随机盐、scrypt、恒定时间比较；同步计算，无显式算法版本 | 已有散列不是明文；需要异步且有并发上限的校验，防止大量登录阻塞共享 API |
| 登录凭据 | 自定义 HMAC 签名的两段令牌，固定有效期 12 小时，通过 Bearer 传输 | 不是标准 JWT；没有逐设备会话、刷新或单令牌退出机制 |
| 后端鉴权 | 校验用户是否有效及 sessionVersion；管理员另校验当前数据库角色 | 应复用这些边界，不能只信前端缓存或令牌里的角色 |
| 前端保存 | localStorage 保存 token 和用户概要 | 同源脚本可读取 token；后续迁移 HttpOnly Cookie，配套 CSRF 防护 |
| 会话恢复 | `/auth/me` 任意异常都会清掉登录信息 | 网络断开、502 等会被当成失效，应区分认证失败与服务暂不可用 |
| 重新登录 | 成功后统一跳首页 | 应返回原题、原标签页路径，并继续查询原提交结果 |
| 退出 | 只删除本地登录信息 | 已复制的 token 仍可用至过期，需要服务端撤销 |
| 修改、找回密码 | 无学生自助改密、无自助找回 | 优先增加改密和人工核验重置；当前未验证手机号不能直接用于自动找回 |
| 管理员重置 | 前端使用统一固定默认密码；后端改密码不递增 sessionVersion | 需改为独立临时凭据及首次改密，并让目标账号旧登录凭据失效 |
| 防滥用 | Nginx 已有通用 API 按 IP 限流，约 10 请求/秒及突发额度 | 不是账号级防猜密码机制；不能简单收紧全部 API，影响同一校园出口下的提交 |
| 审计 | 测试账号生命周期有审计；未发现完整登录失败、改密、会话撤销审计 | 补账号安全事件，禁止记录密码、验证码和完整令牌 |
| 测试账号 | 可创建、启用、停用、逻辑删除；已与正式统计隔离 | 保留现有隔离及停用后的凭据失效规则 |

目前登录签名与“教师 API”及评测临时令牌使用同一持久化签名密钥，但验证用途不同。这里的“教师 API”是题目调用外部模型的临时能力，不是教师人员登录。不能在升级登录时直接轮换共享密钥，或把所有令牌都改走网页登录会话验证。

现有普通用户删除/清空入口包含物理删除及业务清理语义，不是本方案的数据迁移工具。本期不调用这些入口，也不借登录升级重构成绩清理逻辑。

## 3. 目标交互

### 3.1 学生登录与继续做题

1. 继续使用原用户名、原密码登录，支持密码显隐、密码管理器、键盘提交和移动端布局。
2. 登录失败给出明确且不过度暴露账号存在性的提示；提交中禁用重复点击，失败或超时后恢复按钮。
3. 从题目页进入登录后，成功返回原题路径，保留 query/hash；只接受站内合法地址，拒绝外站和协议相对地址。
4. 网络故障时展示“暂时无法验证登录状态”和重试入口，保留本地草稿及任务引用；不把缓存用户当成新的授权依据。
5. 确认登录失效后可以重新登录，并继续查看原 submissionId。登录恢复本身不重复上传、不生成新提交、不重新评测。
6. 多标签页同步退出及账号切换。原账号草稿继续按 userId 隔离，不带入另一个账号。

### 3.2 个人账号安全

第一阶段在个人中心增加“修改密码”“退出其他登录”，说明最后一次成功登录时间及账号异常联系入口。修改密码验证原密码，成功后撤销旧会话，仅为当前经核验操作签发新会话。

“忘记密码”先提供管理员人工核验渠道。管理员依据已有教学登记资料或其他可信渠道核验本人身份，再生成单次临时凭据；未验证的手机号、可编辑学号或姓名不能单独证明账号归属。临时凭据只展示一次，不留明文日志，建议 15 分钟有效；临时登录只允许完成改密、查看必要账号信息和退出，不能直接提交、调用模型或进入完整后台。改密后恢复原账号权限。

人工恢复上线前，由项目负责人指定受理的教学管理员、可信核验渠道和唯一管理员的应急恢复负责人，并登记操作流程。当前尚未提供这些联系人和渠道，不能在产品中虚构联系方式或启用仅凭资料字段的自动找回。若实施时仍未确定，先上线自助改密及联系管理员提示，人工恢复功能保持关闭；不影响现有学生登录和提交。管理员账号不能通过普通学生重置接口恢复，不设置通用后门密码。

第二阶段增加登录设备/会话列表、最近活跃时间、撤销某次登录与退出全部设备。设备信息为辅助展示，不承诺精确定位个人或设备。

### 3.3 管理员界面

保留现有用户管理、测试账号筛选、创建、启用、停用、删除功能与统计隔离。在现有界面增加安全状态、最近登录、密码重置及会话撤销操作和审计查询。重置不再使用统一固定密码。

普通正式学生批量停用、自动删号或改角色不属于本期。管理员 MFA 在具备恢复机制后分步启用，不在唯一管理员尚未完成绑定时强制切断现有入口。

## 4. 分阶段改造建议

### A：账号功能与登录可靠性，优先实施

| 内容 | 建议方案 | 兼容要求 |
|---|---|---|
| 认证状态 | 区分恢复中、已认证、未登录、暂时无法验证；明确错误码 | 仅明确失效清理登录凭据；普通权限不足的 403 不应触发全局退出或跳转循环 |
| 密码操作 | 自助改密、人工核验后重置、临时凭据、改密后撤销旧会话 | 重置只影响目标账号；sessionVersion 单调递增，不全员递增 |
| 服务端退出 | 撤销当前凭据；支持退出全部登录 | 旧令牌没有 jti，以完整令牌的摘要记录撤销，保留至其原始 exp；不能只改前端 |
| 登录防护 | 账号与可信来源 IP 联合控制，渐进延迟、有限冷却；必要时再加验证码 | 不永久锁号；不把校园共享 IP 的少量失败扩散成全班无法登录 |
| 输入与计算 | 新注册、新密码设置长度上限；密码异步校验及有界并发 | 旧登录兼容原有请求预算内的长密码，不能 trim/截断；队列饱和返回可重试提示，不能拖慢提交 API |
| 安全审计 | 成功/失败、改密、重置、会话撤销等事件；管理员可查询 | 账号敏感字段按需脱敏；不采集提交代码或模型请求作为登录日志 |
| 页面可用性 | 返回原题、清晰错误与重试、密码显隐、移动端和键盘体验 | 沿用现有路由与表单组件；不调整任务大厅、题库或成绩逻辑 |

新注册/改密建议使用至少 15 个字符的密码或口令短语，支持空格与 Unicode，最大 128 个字符，并在请求层设置合理字节上限；不强制“大小写+符号”拼凑规则，不要求无原因周期性改密。已有密码不因新规则自动失效。**128 字符上限仅用于设置新密码，不能直接套到存量账号登录**：旧系统没有通用密码最大长度，散列无法反查原长度，应在原有请求体预算内兼容旧长密码，再由用户主动改密。具体输入规范前后端一致。这与 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) 的方向一致。

来源 IP 必须按已知 Nginx/隧道代理链核验；不能信任客户端随意填写的 X-Forwarded-For，也不能误把隧道单一地址当成全部学生的独立来源。现有 Express 未显式设置 trust proxy，实施前需验证实际代理链。登录限流只覆盖认证流程，保留提交、上传和评测网关的原有额度。

找回流程采用统一受理提示、可信身份核验、随机短期单次凭据，参考 [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。短信未接入前不承诺自动短信找回。

### B：会话机制升级，在 A 稳定后实施

采用数据库管理的随机不透明 sessionId。浏览器通过 `Secure + HttpOnly + SameSite=Lax` Cookie 保存，建议使用 `__Host-` 前缀、`Path=/`，不设置 Domain。服务器只存 sessionId 摘要，校验存在性、到期、撤销、用户状态及 sessionVersion。

HttpOnly 能减少脚本直接读取凭据的风险，但不替代 XSS 防护。Cookie 自动随请求发送，必须同步实现写操作的 CSRF token、Origin 校验，覆盖上传 XHR 和普通 fetch；配置明确的允许来源，不把当前宽泛 CORS 原样切成携带凭据的跨域请求。基本原则参考 [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

建议先保持学生当前 12 小时绝对会话有效期，避免升级时改变上课习惯；暂不新增“记住我”的长期自动续期。管理员可采用 30 分钟空闲、8 小时绝对到期及敏感操作再次确认，作为待业务验收的建议默认值，不追溯缩短旧令牌的原定有效期。

管理员分步增加 TOTP 二次验证与单次恢复码；恢复码仅存摘要，先验证恢复路径再强制开启。普通学生不强制 MFA。现阶段不需要为 105 个账号专门部署 Redis 或独立身份服务。

### C：后续能力，本次不作为前置条件

| 能力 | 接入条件与边界 |
|---|---|
| 学校统一身份认证 | 拿到真实协议、标识及测试环境后，用 ExternalIdentity 关联原 User.id；经确认绑定，不按姓名、手机号自动合并 |

| 注册范围 | 本期沿用现有注册方式；是否改邀请码/教学名单，需要单独确认，不能静默关闭自助注册 |

## 5. 数据及凭据兼容设计

### 5.1 保留账号主键与既有身份语义

- 不重建 User，不修改已有 User.id、username、role、isTestAccount；所有历史提交及统计继续关联原 userId。
- 用户名保持当前精确匹配，不自动转小写或大小写无关登录；已发现 2 组大小写冲突，不能直接加归一化唯一约束。
- 手机号未验证且存在重复，不作为首次升级的登录别名或自动找回凭据，不直接加唯一约束。后续“已验证联系方式”独立核验归属。
- 不自动补写 phoneVerified，不把学号转数字，保留前导零。
- 原普通用户物理删除、清空等接口不用于去重、迁移或回退。

### 5.2 增量数据结构

以下是建议模型，由开发在既有 schema 上细化；只新增表和具有兼容默认值的字段。

| 对象 | 用途及必要约束 |
|---|---|
| AuthSession | userId、凭据摘要、凭据类型、sessionVersion、创建/活跃/到期/撤销时间；新 Cookie 会话必须已有有效记录；旧 v1 仅记录被撤销令牌，不误把所有无记录旧令牌拒绝 |
| UserSecurity 或兼容字段 | 临时密码是否待修改、临时凭据到期、密码更新时间等；原账号默认不要求改密 |
| 安全事件 | 复用既有 AuditEvent 能力，补事件类型、操作者、目标 userId、结果、时间及脱敏来源；限制查询权限与留存周期 |
| ResetTicket（需要时） | 若采用重置链接/验证码而非临时密码，存摘要、有效期、用途、已使用标记；二者不无条件重复建设 |
| ExternalIdentity（后续） | provider+subject 唯一，关联原 userId，不复制业务账号 |

账号级限流状态须跨进程/重启有效，先用 PostgreSQL 的小型认证专用记录实现原子计数和过期清理；失败事件和计数与业务提交表分离。先在隔离环境测清登录并发、散列耗时与数据库开销，再设置容量及冷却参数，不在正式课堂直接调大散列成本。

### 5.3 密码格式兼容

第一阶段保留旧 `salt:hash` 核验参数和格式，先改成异步、有并发上限的计算。若后续引入带算法/参数版本的新格式，必须先上线能读取两种格式的版本，再开启新格式写入；只在旧密码成功验证后进行升级，不能离线把旧散列“转换”为新密码。

当前使用 scrypt；是否升级成本参数或换算法以性能实测为依据，不以引入新依赖作为本次目标。参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。回退版本必须能核验已写入的新格式，不能新格式写入后直接退回不认识它的旧后端。

### 5.4 令牌兼容与用途隔离

1. 保留旧 Bearer 登录接口及响应契约；旧 token 缺少 sv 时继续按 0 处理，并始终检查数据库中的账号状态和版本。新增撤销检查，不延长旧 token 的原始 exp。
2. 先发布兼容前后端，再用功能开关开启新 Cookie 登录。可以使用明确的 v2 登录接口，防止旧前端误读新响应。新前端即使 localStorage 没有 token，也能调用会话恢复接口读取 Cookie 会话。
3. 双机制过渡时规则固定：带显式 Bearer 的请求按 Bearer 校验，失败不能回退到 Cookie；同时存在且身份不一致时拒绝，避免用户身份混淆。纯 Cookie 请求走完整会话与 CSRF 校验。
4. 最后一次签发旧网页登录 token 后，至少等待其 12 小时自然到期，再评估停签/停读范围；保留兼容期内必要的旧客户端访问。
5. 教师 API、评测网关、自测令牌继续使用各自 purpose 验证及冻结任务绑定。退出网页登录不应把在途评测判为无权限，也不重新发起评测。用户改密/安全重置可撤销该用户教师 API 租约，已独立签发的运行中评测能力按原任务规则自然结束。
6. 不轮换、不删除现有共享签名密钥；未来若拆分密钥域，先双读，再停止旧签发，等待各用途实际最长有效期和在途任务结束。这个窗口不能只按网页登录的 12 小时计算。
7. 既有环境如果读取密钥失败，应告警并拒绝带病启动，不能静默生成新密钥导致所有凭据失效。

退出成功必须以服务器已撤销为准；服务器不可达时允许本地退出，但提示服务端撤销未确认，不能声称复制出去的令牌已经失效。撤销全部登录、重置密码通过事务更新目标账号安全状态和审计，不回退 sessionVersion。

## 6. 保证业务连续性的发布与回退

### 发布顺序

1. **建立基线**：记录迁移前用户主键、正式账号属性、题目摘要、成绩及提交标识，备份数据库和配置；备份限制权限，并在隔离环境验证可恢复，不导出密码/密钥供文档使用。
2. **隔离开发测试**：使用隔离数据库、测试账号和专用 API；候选 API 不连接正式任务队列、不启动共享 worker。测试账号继续排除正式排行榜和学生成绩汇总。
3. **只增不删迁移**：短锁、超时退出的增量 DDL；没有必要不改老表，不做全量密码重写、账号合并或成绩重算。失败后先保持旧服务运行。
4. **发布兼容版本 A**：同时理解旧数据和未来新会话的后端、可处理两种认证方式的前端先上线，新 Cookie/新密码格式写开关保持关闭。A 阶段的临时凭据/首次改密同样先上线可识别限权状态和改密路由的前端，再开启新重置流程；旧 v45 缓存页面须收到稳定的需刷新升级提示，刷新后进入新改密入口。后端不因旧页面不支持而放开临时会话的业务权限。
5. **逐步开启**：测试账号完整流程通过，再经管理员/受控小范围验证后扩大。A 的稳定版本留作后续 B 的兼容回退基点。
6. **安全切换服务**：沿用现有桥接和排空方案；部署前重新检查队列，不以本次快照的 0 运行任务作为届时无任务的证明。旧 worker 和网关保留到在途任务自然结束，不强杀、不 docker compose down。
7. **观测与验收**：检查登录成功率、认证服务超时、错误退出、上传及评测状态；比对迁移前记录的原始数据，允许正常学生带来新提交和正常分数更新。

### 必须保留的客户端数据

- `prd_draft_${userId}_${questionId}_${revision}`：草稿；保留 autosave、页面离开保存与原版本隔离。
- `prd_submission_${userId}_${questionId}`：正在查看/等待的原任务引用；重新登录后恢复查询。
- 不使用 localStorage.clear，也不通过 Clear-Site-Data 的 storage 指令清空全部站点存储。
- 仍只把平台明确返回的 `404 + code 40001` 视为原任务不存在；网关 HTML 404、5xx、网络失败不得误清任务。
- 认证失败、未过基线、正常评测失败、系统评测异常必须分别处理；不能因为登录恢复再次出现“结果已完成但等待中、按钮灰色”的旧问题。

### 回退规则

- 异常时先关闭新功能写入、保留兼容读取；前后端一起切回已验收的兼容版本 A，保留旧静态资源和标签页兼容。
- 新 Cookie/新密码格式已启用后，不直接退回 release40/v45：旧前端可能不识别 Cookie 登录，旧后端可能不认识新会话、撤销记录或密码格式。
- 不回退全库覆盖上线期间的新提交和成绩；修复或回退认证代码，保留新增安全表、已生效的撤销记录及 sessionVersion。
- 不恢复旧密码，不复活已撤销的登录凭据，不撤销学生正常成绩。
- 如出现正式提交被错误拒绝、运行中评测被认证变更中断、账号越权、原数据变更，立即停止扩大范围，回兼容版本并按原任务 ID 排查；不批量重评历史提交。
- 现有 `/admin` 的 Nginx 保护和独立域名服务保持原配置，认证升级不得连带改动其他站点。
