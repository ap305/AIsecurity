## 已实现的业务闭环

- 题目管理：Markdown、算法/模型/蒸馏/Agent 能力、参数契约、固定角色、关联场景、环境包、基线和评分参数、分阶段自测及发布版本。自测证据同时绑定包摘要、完整题目配置、固定角色和模型池修订；配置变化后须重测。
- 提交：会话身份、题目版本、代码与参数摘要、幂等受理、不可变配置快照、持久评测队列、本人历史和公开结果。旧执行入口不再绕过新规则运行学生代码。
- 基础成绩：独立最高分和总分表，更高有效分才增加差额，等分低分不改变达到时间；改题清零扣除原贡献，迟到旧版本结果只保留历史。
- 动态攻防：统一大于等于基线、按账号去重、相反角色、排除本人、合格空池100%、正常全败0%、异常不计分、完整快照发布、失败保留旧版、动态重评及独立题榜。
- 模型服务：全局资源池、默认模型项、配置修订记录、发布时冻结模型及参数；提交网关按任务权限和预算转发，学生不能覆盖地址、模型或平台凭证。
- 教师 API：服务可用后起算两小时、服务端逐请求校验、到期手动续期、禁止提前续期、管理员查看和撤销。账号和题目共同限定租约。
- 学生界面：基础/攻防两个列表，攻击和防御分别直达独立解题页，左题面右代码，能力开关、实际上传进度、轮询恢复、历史、成绩、租约与个人资料。学号和手机号选填，前导零保留，公开榜单不展示这些字段。
- 成就显示待开放；实际手机验证码服务与成就公式仍按 PRD 后续阶段处理。

## 设计决策

1. D-23 未作业务定稿，本次选用账号加题目的一份租约；查询预算按题目配置。首次开启失败不消耗两小时时间，有效时重复开启不延长时间。
2. 排名末级排序使用用户 ID，保证分数和达到时间完全相同时结果稳定。
3. 下架保留审计资料与基础历史成绩、阻止新提交和教师访问；攻防有效算法退池并触发受影响成绩更新。
4. 环境包使用固定镜像和平台生成的受控 Compose。可信判分器、学生程序、对手程序分处不同容器，通过带凭证且有大小及超时限制的 JSON RPC 调用；学生程序只挂载自己的材料。生产应配置镜像摘要及资源上限，不执行上传包中的宿主机命令。
5. 每次正式提交/重试使用独立执行实例；异常状态保留解释，系统错误不伪造0分。系统故障最多自动尝试三次，管理员可对仍有效的异常任务重试；重评失败保留旧分。
6. 单对手胜负由声明的指标与阈值按 `>=` 计算；结果保留指标及脚本声明供审计，不以未受配置约束的布尔字段覆盖胜负。

## 验证方法

`pnpm test` 执行规则测试、真实 PostgreSQL 引擎的隔离内存库集成、HTTP 接口、环境包安全和 Compose 调度契约测试。测试库使用 PGlite，独立监听随机本机端口，不读取现有数据库配置。其单连接模式验证业务事务和幂等，不代替生产 PostgreSQL 的容量测试。

`pnpm build` 生成 Prisma 客户端并编译后端和前端。浏览器检查使用独立测试数据服务与本地 Vite。Compose 测试通过可注入命令执行器检查材料隔离、参数、结果契约和清理；真实容器运行用单独开关执行，不能将模拟命令的测试等同于真实 Docker 验收。

三个教学评测包提供可执行算法、参数推理和攻击/防御基线及对抗样例。正式题库需要将真实评测脚本接到安全调用契约，使用出题人的标准样例逐题自测后发布；平台样例不替代每道专业赛题的算法验收。

## 迁移和运行

新增迁移在 `services/quiz-svc/prisma/migrations/20261014000000_prd_v11`，同时补齐旧代码通过 schema push 引入而未记录到迁移链的字段。旧 `Submission`、`UserScore` 和归档材料保留。

`services/quiz-svc/scripts/migratePrd.ts` 默认只生成差异报告。显式指定隔离数据库的 `DATABASE_URL` 后执行 `pnpm --filter quiz-svc migration:prd:preview --report=...`。报告区分有效基础成绩、过期版本、身份无法还原记录以及待转换题目；`--apply` 才会重建新基础成绩表。上线前先备份数据库和材料目录，暂停提交并等待执行任务完成。

历史攻防成绩不直接变为新动态成绩。历史算法须通过当前基线和完整对手评测后入池。未配置安全环境包的旧题保留资料，提交时明确提示待配置；不能静默回落到宿主机 Python 执行。

静态题库与代码资产的盘点见 [迁移清单](prd-v1.1-migration-inventory.md)。实际已发布题目及历史提交需以目标数据库的只读迁移预览补齐；本次未连接业务数据库。不要用现有 `prisma/seed.ts` 代替迁移：该脚本包含删除旧题和提交的重建操作。

上线顺序为：备份数据库及材料目录，暂停提交并等待任务结束；先在数据库副本执行结构迁移和只读差异报告；核对最高分、达到时间估算、缺失账号和旧题转换清单；显式应用基础成绩重建；逐题完成安全包、自测及真实容器验收；最后切换服务。迁移命令先占用报告文件，已存在或不可写时不会启动数据写入。

回退时先停止新提交和工作进程，保留切换后的新增记录供核对，再按版本检查点回退代码。涉及数据恢复须使用切换前备份并核对新增记录，不能直接以旧榜单覆盖新成绩；已变更题目的失效分数不得恢复。新增结构迁移保留旧业务表，不提供无检查的逆向删除脚本。

Docker 执行器配置、挂载路径映射、清理恢复和真实容器验收命令见 [评测运行说明](prd-v1.1-evaluation-deployment.md)。本次未执行生产数据迁移或生产发布。
