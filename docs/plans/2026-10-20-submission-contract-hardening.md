# 提交代码完整性与接口错误提示加固

目标：覆盖已发布 77 题的统一评测入口，让确定性的学生代码错误在评分/模型调用前终止并给出可操作提示；保留旧成绩及正常提交流程。

边界：沿用已授权的自主修复和部署范围；不改评分、题目版本、参考答案或学生记录。静态分析只读取源码 AST，不运行源码或加载权重；分析必须在该任务的隔离容器内。只对冻结模板明确要求完成的函数判断空实现，注释 TODO、合法 None、抽象类和未知动态实现不得一概拒绝。

- [x] 对 77 题冻结模板、运行时校验和历史失败做只读覆盖审计。
- [x] 先写测试复现：语法/缩进、未填写槽位、None 返回、缺入口、合法边界、错误提示丢失。
- [x] 统一 Compose 入口加入隔离静态预检；冻结 answerTemplate 随评测输入传递；只检查本次候选，不把对手错误归到学生。
- [x] 保留白名单内的具体接口错误与安全行号，阻止原始异常、路径、数据或任意评测文本进入提示。
- [x] 回归检查失败仅处理一次、不计分、保留原算法/最高分，正常代码与零分结果不受影响。
- [x] 本地及 Linux 隔离测试、代码复核、提交和版本标记后构建。
- [x] 低负载窗口部署，备份并核对题目、提交和成绩；公网接口复核；整理覆盖结果和限制。

实现位置：`submissionPreflight.ts` 提供无执行 AST 分析程序和安全结果解码；`composeJudge.ts` 在启动评分器前执行预检；`studentFailureMessage.ts` 统一允许公开的错误提示；`evaluationWorker.ts`、`arenaScoring.ts` 传递冻结模板和安全原因。已存在的各题运行时返回值检查继续执行。

验收不以“能检测所有程序错误”为承诺：动态生成、复杂控制流无法静态确定的情况交由隔离运行时处理；算法逻辑错误仍由正式评测判定。上线不重试历史失败、不改成绩。
