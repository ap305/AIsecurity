# 测试账号完整提交流程验收计划

**Goal:** 用管理员新建的测试账号通过正式HTTPS API走通登录、提交、真实容器评测、轮询及重新查看结果，并验证启用/停用；保护正式学生提交、排行榜和已有成绩。

**Scope:** 上一版已实现测试账号创建、启用、停用、逻辑删除及统计隔离；本次补充真实评测端到端验收。优先使用官方参考代码和低资源、无外部模型调用的代表性基础/攻防题；如发现代码问题，先隔离复现和失败测试，再最小修复并提交打标、安全发布。

## 约束

- 正常管理员登录；密码和token只在进程内使用，不存源码/Git/报告，不读取auth-secret.json签令牌。
- 不改题面、门槛、评分公式或正式学生提交，不批量重试，不重置正式成绩。
- 测试账号标记必须为isTestAccount=true；测试成绩不进入正式榜/学生汇总，也不进入正式对手分母。
- 每次真实评测前只读检查正式评测队列，选择空闲窗口，串行提交低资源样例；有正式任务时等待，不强占、不停止学生任务。
- 通过HTTP/JSON、容器和数据库证据验收；不使用Playwright或截图。
- 原有 `.superpowers/` 未跟踪工作不改动。

- [x] 2. 管理员新建测试账号，验证学员入口登录、题目可见、提交合法参考代码、幂等重发、真实评测完成及结果详情/历史/大厅分数一致。

- [x] 5. 本次未发现需修复的功能异常，无业务代码或服务变更；保留验收账号为停用状态及其审计/测试结果，正式数据指纹与健康已复核；保存报告并同步经过审查的文档。

## 验收决定与结果

- 为便于用户直接看到「启用」按钮，验收账号最后保留为停用，而非从列表逻辑删除；管理员仍可删除它。随机初始密码不落盘，后续可按既有密码重置功能处理。
- 实测4次提交：B02=100分；启用后B02=0分且最高仍100；A26=100分（无正式对手规则）；D26=100分（正式对手1/1）。全部completed且attempts=1，详情/历史/大厅结果一致。
- 正式94账号、160提交、既有成绩/槽位/算法/任务及24个池的行指纹均保持；榜响应不变，观察期间无正式活动任务，最终无遗留eval容器。
- 启用/停用当前已上线，重复状态操作、旧会话失效、重新登录及结果保留已真实验证。详见 `docs/validation/2026-10-27-test-account-complete-flow.md`。
