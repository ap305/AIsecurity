## 实施顺序与分工

1. 冻结配置、版本、提交和结果契约；新增可向前迁移的数据模型，保留历史记录。
2. 主任务：题目版本/发布、基础最高分与榜单、鉴权、API池、教师租约、持久任务队列和集成。
3. 子任务 A：攻防资格、按用户去重的有效版本、完整对手快照、动态重评、独立排名和旧入口兼容。
4. 子任务 B：安全环境包导入、受控独立 Compose 执行、结构化结果检查、超时清理和评测样例。
5. 子任务 C：两个大厅、统一独立解题页、完整出题表单、模型池与租约管理、注册与榜单展示。
6. 集成与验收：类型检查/构建、规则边界与并发测试、隔离测试数据库中的 API 链路、浏览器页面检查、资产迁移演练和部署说明。

## 关键技术选择

- 题目 `revision` 每次发布内容变化递增；提交冻结 revision、完整评测配置及材料摘要。历史结果继续可追溯。
- 基础榜使用独立 `BasicScore` 与 `BasicTotal`，不继续读取旧混合 `UserScore`。只在有效成绩严格提高时累计差额；事务保护并发；当前总分达到时间独立保存。
- 攻防角色以两条题目记录呈现，`scenarioId` 与 `evaluationVersion` 决定兼容池。新版本完整评测成功后才替换；重评保持旧分直到完整快照完成。
- 新提交通过登录会话识别账号，不接受客户端指定归属；学生只能读本人材料，公开列表仅返回公开字段。
- API池配置不可变版本化；题目发布冻结所选资源，默认项改变不改已有绑定。网关不接受学生覆盖模型/地址/密钥。未配置服务真实报错，不以 mock 成绩冒充评测。
- 临时教师 API 采用账号加题目的一份租约作为可调整的技术默认值；有效期两小时从服务健康检查通过后起算；到期明确续期。D-23 尚无业务定稿，默认值、额度与部署参数在配置中记录，后续可调整，不冒充已确认规则。
- 未定容量、上传大小、超时和调用预算使用可配置上限并在题目中声明。D-21 成就公式与 D-22 实际手机验证仍属后续范围，本期保留状态和入口。
- 下架阻止新提交与教师调用；保留历史成绩/材料。已有提交按冻结版本完成，但不得让失效版本重新计入当前成绩。管理员撤销租约立即阻断后续调用。

## 新增需求：管理员学生逐题成绩（2026-10-14）

管理员新增“学生成绩”页面，可按姓名、账号、学号搜索学生；列表显示基础题总分、已计分题数、已提交题数和最近提交时间。选择学生后，按已提交题目分别展示题名、题目类型/攻防角色、当前有效分、累计与当前版本提交次数、最新提交状态、成绩达到时间。从用户管理也可直接进入指定学生明细。

基础题采用当前版本最高有效分，与全范围基础排行榜一致；题目下架但版本未变化时保留该分数。攻防题使用当前有效算法的动态胜率，不取历史最高值，不加入基础总分。正常0分必须显示0，未计分显示空值并说明原因；新提交失败不覆盖原有效成绩；题目版本变化后旧分失效，旧提交仍保留。

接口仅管理员可访问，不返回学生源码、权重路径、密码或模型密钥。无提交学生也可查看，明细为空。验收包含权限、搜索分页、最高分与最新提交区分、动态攻防0分、版本失效及总分一致性。

## 服务器验收发现与修复

独立测试站使用50081/14002/15432端口及新测试库。首轮真实Docker验收发现服务器内部DNS无法解析容器服务名，而同一隔离网络内的IP通信正常。此前示例将该故障笼统归为学生代码异常，造成自测未通过和发布阻断；失败记录保留，不计作验收通过。

修复后任务先启动学生/对手/网关依赖，校验容器ID、project、健康状态、指定internal网络及成员关系，再把本次任务的内部IP写入只读评分上下文。评分容器使用`--no-deps`启动，避免依赖被重建导致IP变化；启动、检查和评分共享总时限，全部失败路径仍执行本project清理。学生与对手保留独立网络，不修改服务器全局网络设置。

RPC客户端区分学生代码422、基础设施故障、协议中断和超时，三类教学示例分别返回`student_error`、`system_error`或`timeout`，异常不携带成绩。基础设施错误可由队列重试，避免将部署故障错误归责学生。
