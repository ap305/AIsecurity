# 模型用量监控与安全修复验收

## 范围与口径

按用户明确选择，本次只启用统计与告警，累计阈值不阻止学生提交或中断评测。保留现有每次评测的固定预算、模型、响应快照、评分公式与历史成绩。

- 管理入口：`/admin/model-usage`。按北京时间展示今日、近 7/30 天、累计，以及模型、题目和账号分组；测试账号的实际调用纳入用量。
- 上游尝试、成功、失败、待完成、缓存命中分别记录。缓存命中不重复计算上游次数或 token；没有 provider usage 的调用明确标记未知，不推算金额或回填历史账单。
- 预警阈值默认：平台每日 10,000／累计 100,000；账号每日 4,000／累计 20,000。80% 提醒，达到阈值告警。管理员可调整；服务与数据库均仅允许 observe 模式。
- 上游 401／402 即时告警，同一上游十分钟内连续三次限流、超时或连接失败告警；重复事件合并，已确认告警遇到新事件重新打开。通知位于管理页面，无外发消息。
- 健康检查要求有效登录、按配置缓存 30 秒；错误响应不返回原始 provider 内容。配置参数的凭证检查在服务端执行，合法 JSON Schema 字段定义仍可保存。
- 账本不保存提示词、回复正文或密钥。每次监控调用等待最多 200ms，事务设短超时；迟到 begin 与 finish 保持关联。监控不可用时不改变评测响应，可能存在未知或缺失记录，不能将本账本当作供应商完整账单。

## 发布保护

仅新增三张无业务表外键的 ModelUsage 表，旧 schema 与既有迁移内容必须保持一致。发布流程要求新鲜数据库备份、独立恢复验证、克隆正常登录和模拟网关验收，再进行兼容 API 桥接、队列排空与切换；停止宽限 25 小时。

公网保留原有资源供已打开页面使用，保持另一域名路由与证书不变，为用量管理 API 保留 `private, no-store`。部署记录与备份留在受限运维目录，不进入源码仓库。实际生产发布及数据比对结果将在验收后追加。
